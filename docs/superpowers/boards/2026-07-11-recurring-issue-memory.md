# 重复问题记忆

## 2026-07-11 用户授权页反复跳登录

- 症状：
  - 点击“用户授权”后直接回到登录页。
  - 重新登录后再次进入，仍然会被踢回登录页。
- 触发条件：
  - 当前租户 ID 还没有就绪，或平台态默认拿到 `tenantId = 0`。
  - `frontend/src/views/IamUserManagementView.vue` 在页面挂载或刷新时直接请求用户/角色接口。
- 根因：
  - `backend/xuan-iam/src/main/java/com/xuan/erp/iam/application/service/IamUserApplicationService.java` 要求 `tenantId > 0`。
  - 用户授权页在租户无效时仍请求 `/api/iam/users` 和 `/api/iam/roles`，导致页面初始化阶段先打出无效请求。
  - 这类错误在前端表现上容易被误判成“登录失效”或“授权后又回登录页”。
  - 前端此前对所有 `401` 都立即清空 token 并跳登录，单个业务接口误报未认证时，会把页面问题放大成整站掉线。
- 本次修复：
  - 后端允许 `tenantId = 0` 查询平台用户列表和平台用户角色。
  - 前端仅在 `tenantId < 0` 或非法数字时提示“请输入有效租户 ID”。
  - 平台级用户角色分配改为只读查看，不能在用户授权页直接修改。
  - 前端 `401` 先用 `/api/iam/auth/current-user` 探测会话是否真实失效，只有确认失效才执行登出跳转。
- 固化规则：
  - 所有依赖租户上下文的 IAM 管理页，都要明确区分“业务租户态”和“平台态”。
  - 业务租户页不能误把平台态 `tenantId = 0` 当成非法值直接拦截。
  - 平台级高危对象默认优先只读展示，编辑能力必须单独设计，不要顺手复用租户内写链路。
  - 新增同类页面时，必须补对应前端校验脚本和后端测试，防止这个问题再次回归。
- 检索关键词：
  - `用户授权`
  - `跳登录`
  - `tenantId = 0`
  - `请输入有效租户 ID`
  - `verify:user-role-grant`
