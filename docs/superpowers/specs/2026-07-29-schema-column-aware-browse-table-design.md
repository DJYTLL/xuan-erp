# 支持列权限的 Schema 浏览表格设计

## 背景

当前组件中心中的“浏览表格”通过 [frontend/src/views/ComponentCenterView.vue](/D:/xuan-erp/frontend/src/views/ComponentCenterView.vue) 直接提供：

- 列配置数组
- 示例数据
- 状态列 slot
- 操作列 slot
- 工具栏动作

而表格本体 [frontend/src/framework/components/XuanBrowseTable.vue](/D:/xuan-erp/frontend/src/framework/components/XuanBrowseTable.vue) 主要负责：

- 基础表格渲染
- 列设置
- 列顺序调整
- 固定列
- 分页大小与密度偏好

这种模式已经比“全部写死 template”更进一步，但还不够通用，原因有三点：

1. 页面结构信息分散在页面文件和 slot 里，难以批量复用。
2. 还没有把列权限作为一等能力纳入表格协议。
3. 后续很多业务页都会复用该组件，继续沿用“页面手写列 + 局部 slot 拼装”的方式，维护成本会越来越高。

## 目标

把 `XuanBrowseTable` 升级为一个**支持列权限三态的 schema 通用表格组件**，让未来业务页只需提供：

- 表格 schema
- 行数据
- 列权限结果

即可渲染出一致的浏览表格体验。

本次设计直接支持三态列权限：

- `VISIBLE`
- `MASKED`
- `HIDDEN`

## 约束

- 本轮仅做前端组件层设计与实现，不改后端协议，不新增数据库迁移。
- 表格组件本身不直接请求 IAM 接口，只消费上层传入的列权限结果。
- 第一批落地页是组件中心中的“浏览表格”示例；真实业务页迁移放到后续执行阶段。
- 现有列偏好能力必须保留，包括：列显示、列顺序、固定列、分页大小、密度。

## 设计原则

### 1. 表格必须长期通用

组件不能围绕“组件中心示例页”反向定制，而是要面向未来真实业务页设计。后续商品、租户、订单、库存等页面都应能复用同一套 schema 协议。

### 2. 列权限是一等能力

列权限不能作为额外补丁挂在页面层。schema 中每一列都要能表达其字段权限元信息，表格内部统一计算最终展示状态。

### 3. 表格只负责渲染与策略合并

表格接收“列权限结果”，但不负责 IAM API 调用。业务页或上层容器负责取数和权限结果拼装。

### 4. 优先保证协议清晰

即使第一版实现量稍大，也要把 schema 协议设计清楚，避免后续真实页面大规模接入时再次改协议。

## 总体方案

### 1. 新增 Schema 驱动入口

`XuanBrowseTable` 改为以 `schema` 作为主输入，不再把工具栏、列、操作列等能力分散在大量零散 props 和 slot 中。

页面侧使用方式收敛为三块：

1. `schema`
2. `rows`
3. `columnPermissionSnapshot`

其中：

- `schema` 负责描述页面长什么样
- `rows` 负责承载数据
- `columnPermissionSnapshot` 负责描述当前用户对每个字段的最终访问方式

### 2. Schema 分层

为避免一个超大对象难以维护，schema 拆成以下层次：

- `tableSchema`
- `toolbarSchema`
- `columnSchema[]`
- `rowActionSchema[]`
- `paginationSchema`
- `emptyStateSchema`

这样既能表达完整结构，又便于未来页面按需组装。

## Schema 结构设计

### 1. 表格顶层 Schema

顶层结构建议包含：

- 表格编码 `tableCode`
- 页面编码 `pageCode`
- 是否支持多选
- 操作列宽度
- 默认密度
- 工具栏配置
- 列定义
- 行操作定义
- 分页配置
- 空态配置

其职责是描述“这个浏览表格整体长什么样”。

### 2. 列 Schema

每一列都应至少包含以下信息：

- `key`：列唯一标识
- `title`：列标题
- `prop`：对应行数据字段
- `width` / `minWidth`
- `fixed`
- `align`
- `visibleByDefault`
- `displayType`
- `formatter`
- `resourceKey`
- `columnKey`
- `maskType`
- `allowUserToggle`

其中列权限相关字段的职责如下：

- `resourceKey`：和 IAM 资源对齐
- `columnKey`：和 IAM 字段编码对齐
- `maskType`：描述默认脱敏策略
- `allowUserToggle`：是否允许用户在“列设置”中手动关闭该列

### 3. 单元格展示类型

为了减少每个页面都回退到 slot，自定义渲染采用受控的 `displayType`：

- `text`
- `tag`
- `masked-text`
- `actions`

第一版仅支持上述类型，足够覆盖组件中心当前这张表，也足够覆盖大多数基础浏览页。复杂渲染后续可增加 `displayType`，而不是一开始把协议做得无限开放。

### 4. 工具栏 Schema

工具栏 schema 负责定义：

- 左侧信息区
- 右侧动作区
- 是否展示密度切换
- 是否展示列设置
- 附加按钮

这样“刷新”“导出”“新增”“列设置”等动作都能进入统一协议，而不是散落在每个页面 slot 中。

### 5. 行操作 Schema

行操作 schema 负责描述：

- 按钮文本
- 类型
- 可见条件
- 禁用条件
- 动作 key

表格组件只渲染动作，不直接执行业务逻辑。页面层通过动作 key 接收事件并执行真正的业务处理。

## 列权限设计

### 1. 三态模型

表格内部统一支持三种访问模式：

- `VISIBLE`：显示原值
- `MASKED`：显示脱敏值
- `HIDDEN`：整列不渲染

这是当前方案的基础能力，不做降级为“只显示/隐藏”。

### 2. 权限快照输入

表格接收一个结构化的 `columnPermissionSnapshot`，按 `resourceKey + columnKey` 查询字段权限结果。

组件不关心这个快照来自哪里，只做消费和合并。

### 3. 最终列展示优先级

最终列是否显示，按以下优先级计算：

1. **列权限结果**
2. **用户个人列偏好**
3. **schema 默认值**

具体规则：

- 如果列权限为 `HIDDEN`，该列不渲染，用户也不能通过列设置重新打开。
- 如果列权限为 `MASKED`，该列渲染，但内容走脱敏逻辑，用户不能切回明文。
- 如果列权限为 `VISIBLE`，再由用户个人列偏好决定是否显示。
- 如果没有任何列权限结果，回退到 schema 默认值和用户个人偏好。

### 4. 列设置面板的权限感知

列设置面板不能继续只是普通 checkbox 列表，而应表现出列的权限状态：

- 明文可见：允许勾选显示/隐藏
- 脱敏可见：允许保留显示，但提示“当前列受列权限约束，按脱敏方式展示”
- 权限隐藏：置灰，提示“当前列已被列权限隐藏”

这样用户能看懂为什么某些列不能改，而不是只看到“勾不上”。

### 5. 脱敏策略

第一版脱敏只做通用文本层处理，不把所有业务格式化都塞进组件里。

优先支持：

- 手机号
- 身份类编码
- 通用部分隐藏

当列 schema 中定义了 `maskType` 且权限结果为 `MASKED` 时，表格使用统一脱敏逻辑。

## 组件职责边界

### 表格组件负责

- schema 解析
- 列权限结果合并
- 列设置面板渲染
- 单元格基础渲染
- 偏好保存与读取
- 向页面抛出动作事件

### 页面负责

- 拉取数据
- 拉取列权限结果
- 组装 schema
- 处理工具栏动作
- 处理行操作动作

这个边界必须固定，否则组件很快会因为耦合具体业务接口而失去复用价值。

## 向下兼容策略

为了降低一次性改动风险，组件实现分两阶段：

### 阶段 1

`XuanBrowseTable` 内部增加 schema 渲染通路，组件中心的“浏览表格”先切到新 schema 协议。

### 阶段 2

确认 schema 协议稳定后，再逐步迁移真实业务页。

如果组件内部还保留旧 `columns + slot` 模式，也只作为临时兼容，后续真实页面应统一迁到 schema 协议。

## 首批落地范围

本轮仅覆盖以下内容：

1. 重构 `XuanBrowseTable` 为 schema 主入口
2. 为列 schema 引入三态列权限元信息
3. 为列设置面板加入权限感知
4. 组件中心“浏览表格”完整迁移到 schema 模式
5. 组件中心用 mock 权限快照演示 `VISIBLE / MASKED / HIDDEN`

## 暂不处理

- 真实业务页批量迁移
- 查询区强制 schema 化
- 表格内部直接请求 IAM
- 服务端动态下发表格 schema
- 超复杂自定义单元格渲染协议

## 验证要求

实现阶段至少验证以下内容：

1. schema 能完整渲染当前组件中心浏览表格
2. 列设置仍支持：
   - 显示/隐藏
   - 上下移动
   - 左右固定
3. 分页大小和密度偏好仍能保存
4. `VISIBLE` 列显示原值
5. `MASKED` 列显示脱敏值
6. `HIDDEN` 列完全不渲染
7. 权限锁定隐藏列不能在列设置面板中被重新打开
8. 权限锁定脱敏列不能在列设置面板中被切回明文

## 后续扩展路径

当这套 schema 在组件中心验证稳定后，后续真实业务页接入的标准流程应是：

1. 页面定义或引用自己的浏览表格 schema
2. 页面拉取行数据
3. 页面拉取当前用户列权限结果
4. 页面把三者传给 `XuanBrowseTable`
5. 表格内部统一产出最终展示结果

这样后续接入商品、租户、订单、库存等页面时，不需要再为每个页面重新发明表格协议。
